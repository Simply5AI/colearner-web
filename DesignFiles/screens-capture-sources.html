NestJS Endpoints
GET /api/capture/stats — Returns today's capture count, total concepts, daily limit remaining.
POST /api/capture/youtube — Body: { url, options: { autoTranscript, questionTypes } } → Queue extraction.
POST /api/capture/web — Body: { url } → Fetch via @mozilla/readability, queue extraction.
POST /api/capture/document — Multipart: file upload (PDF/DOCX) → Parse, chunk, queue extraction.
POST /api/capture/audio — Multipart: audio file OR { recordingBlob } → Whisper transcribe, queue extraction.
POST /api/capture/video — Multipart: video file → FFmpeg audio extract, Whisper transcribe, queue extraction.
GET /api/capture/:id/status — SSE endpoint for real-time extraction progress updates.
Source Architecture Notes
All rings share the same downstream pipeline: text → chunk (4,000 chars, 300 overlap, max 5) → Pass 1 llama3.2:3b → Pass 2 gemma2:9b.
Sources differ only in the input adapter: Source 0 (YouTube transcript API), Source 1 (Readability + fetch), Source 2 (pdf-parse/mammoth), Source 3 (whisper.cpp), Source 4 (ffmpeg + whisper.cpp).
Privacy: All rings follow the same SHA256 rule — never store raw URLs, filenames, or source content. Only hashes + extracted concepts.
Daily limits: Free tier = 5 captures/day across ALL rings combined. Pro = unlimited. Enterprise = unlimited + priority queue.
File uploads use multer middleware on NestJS with size limits: docs 25MB, audio 100MB, video 500MB.
Live recording (Source 3): MediaRecorder API on frontend → Blob → upload same as file.
State Management
Zustand store: useCaptureStore — { expandedSource, selectedFile, captureUrl, isRecording, recordingTime, dailyStats }.
Accordion: only one ring expanded at a time. Click expanded header to collapse. Click another to switch.
File upload: react-dropzone for drag-and-drop with file type validation per ring.
Live recording: MediaRecorder + AudioContext for waveform visualization.
After "Start Capture": redirect to /capture/processing/[captureId] with SSE progress tracking.
