# B09 web practice hub, start flow, summary and answer sheet (W2)

Implementation date: 19 October 2026. API stays **/api/v1**. The platform practice module (agents PD1/PD2) and the AI pack were being built in parallel, so this slice is written to `agents/contracts/B09-contracts.md` and verified with **mocked HTTP only** (a test double that follows the contract). No git commit, migration, deployment or model call was made, and nothing here proves the live platform, permissions or model behaviour. The session player (L10) and the seven question renderers belong to agent W1 and are not part of this document.

## Routes

| Route | What it does | Code |
|---|---|---|
| `/learn/practice` (`?tab=past`, `?planId=`) | L9 hub: Today (or Games for kids) and Past sessions tabs. States: default, caught up, no content, past sessions, loading, denied, unavailable with retry. | `components/practice/hub.tsx` (`HubView`), `hub-screen.tsx` (`HubScreen`) |
| `/learn/practice/start?scope=&id=&planId=` | Gets or creates the question set when the target needs one, polls with backoff while Co makes it, creates the session with a stable client id, then `router.replace` to `/learn/practice/session/[sessionId]` (W1). | `start-screen.tsx` (`StartScreen`), `states.tsx` |
| `/learn/practice/summary/[sessionId]` | L11: Great, Tough, Loading, Feedback unavailable, by band. | `summary.tsx` (`SummaryView`), `summary-screen.tsx` |
| `/learn/practice/answer-sheet/[sessionId]` | Answer sheet of a finished session, with "Ask Co to check again" for answers whose feedback was unavailable. | `answer-sheet.tsx`, `answer-sheet-screen.tsx` |
| `/dev/practice` | Development-only harness (see below). | `app/dev/practice/page.tsx` |

All sit in the `(learn)` group, so the server layout still repeats `requireLearnerAccess()` (child cookie wins, no fallback to an adult). Navigation: `studentNavigation` Practice/Play item now points at `/learn/practice` and stays lit on every `/learn/practice/**` route (and the retained legacy `/practice` and `/recall`), `ChildLearnShell` gained a Practice/Play item, and the kids "Play" tile on home links to `/learn/practice`.

## `linkHref` and PRACTICE links

`Link` gained the optional `scope` (`HUB | DUE | MATERIAL | LESSON | TOPIC | PLAN_EXAM | SET`, additive; the schema is shared with the lesson contract so a lesson's "Practice now" keeps its scope). Mapping: `HUB`, and `DUE` without an id, open `/learn/practice` (as the contract says). `MATERIAL`, `LESSON`, `TOPIC` (with `planId`), `PLAN_EXAM` (id = plan) and `SET` open `/learn/practice/start?scope=…&id=…[&planId=…]`. A PRACTICE link with an id but no scope is **not guessed at** and stays disabled with the server's reason. Ids are validated against `^[a-zA-Z0-9_-]{1,128}$`. The hub gives its own review button the start route (`/learn/practice/start?scope=DUE`) so "Start review" on the hub does not link back to the hub.

## BFF and client

`app/api/learn/[[...path]]/route.ts` allowlist gained exactly these routes under `practice/`: GET `hub`, `sets/:id`, `sessions`, `sessions/:id`, `sessions/:id/items/:n` (n is 1 to 3 digits), `sessions/:id/summary`, `sessions/:id/answer-sheet`; POST `sets`, `sets/:id/{retry,cancel}`, `sessions`, `sessions/:id/items/:n/{answer,hint,skip}`, `sessions/:id/complete`, `attempts/:id/regrade`. Nothing else under `practice/` (no PUT or DELETE, no worker, reward or internal route) exists: any other path is a 404 before a credential is read. Query strings are forwarded only for `practice/hub` (`subjectId`, `planId`) and `practice/sessions` (`cursor`, `limit`); the overview filters are unchanged. Same-origin writes, child cookie precedence, membership header and error hiding are unchanged.

`lib/api/practice.ts` holds the contract interfaces and Zod schemas (each `satisfies` its interface): `QuestionView` and `PracticeAnswer` discriminated unions, hub, set summary, session row, session state, history page, `AnswerReceipt`, summary, answer sheet, plus `practiceApi` (every allowlisted call), `answerIssue` (kind equals the item kind and ids belong to the question), `sessionScopeFor`, `modeForScope`, `newClientId`. `QuestionView` is strict: unknown keys are rejected, and a question carrying `answerKey`, `correctOptionId`, `explanation`, `rubric`, `modelAnswer`, `accepted`, `hints`, `isCorrect` or similar (at any depth) is refused whole, so a key is never held in memory. A receipt that carries `revealedAnswer` without `correctAnswerRevealed` is refused. `learn-request.ts` gained safe copy for `SESSION_*`, `ITEM_OUT_OF_ORDER`, `ATTEMPTS_EXHAUSTED`, `HINT_OUT_OF_ORDER`, `HINTS_DISABLED_IN_EXAM`, `ANSWER_*`, `NO_QUESTIONS_AVAILABLE` and the set and capability errors. `POLICY_BLOCKED` is still the only code whose server text is shown.

## Behaviour

- **Hub (L9).** Kids ("Play"): game tiles with 0 to 3 effort stars, "Remember" review tile, "Big test" tile, a sticker-free timeline of rounds with stars only (no scores, no answer-sheet entry), read-aloud on the title (device voice only, absent without one). Tweens: review estimate from the server ("5 cards, about 4 minutes"), subject filter chips over the sets, subject cards, teacher practice with progress, mock tests, recent sessions list. Teens: reviews due, weak spots (an honest empty state until measured mastery exists, B11), mock tests, practice by material, set by your teacher, past sessions table with Answer sheet links. Recall and exam are distinct in words and form: practice and review say "Hints and extra tries are allowed", the mock test has a dashed border, a timer icon and "Timed. One try for each question, no hints, and answers only at the end." Kinds the server says are unavailable (code, voice) are listed with its reason. A set still being made or failed shows its status and a link to the start page, never a working start button; a disabled start shows the server's reason.
- **Start.** One idempotent get-or-create of the set (a query, so React's double mount cannot send it twice), then polling of `GET sets/:id` with the lesson backoff while QUEUED or RUNNING (survives refresh). Generating, failed (retry offered only if the server says retryable; double press is one request; a newer set id is followed), stopped (make again) and typed refusals have their own plain states. The session request carries a client-generated `clientSessionId` kept in `sessionStorage` for 30 minutes, so a refresh after a lost response repeats the same idempotent request; it is cleared once the learner has moved on, so "Play again" later starts a new session. Mode: DUE is REVIEW, PLAN_EXAM is EXAM, everything else PRACTICE.
- **Summary (L11).** Kids: "You did it!" or "That was a tricky one!", stars only, no score, no count of misses, Play again or Look again (the lesson recap), Home or Later. Tweens: score, stars, the missed questions with "Review it" (the lesson when the miss has a source, otherwise the answer-sheet item). Teens: accuracy, time, first-try count when it differs, concepts to revise, next review date from the server. Tough sessions never say fail: "Quick recap", "Try again later". Teach-back is shown, **disabled**, with the server's reason (B11), even if the server says enabled. A reward is drawn exactly as returned (one per session, so a refresh shows the same stars); XP, level and readiness render only if the server sends a number (always null in B09). Unavailable grading shows a plain note (kids get no count) and says those answers are not in the score.
- **Answer sheet.** Each answer has a written mark (Correct, Partly right, Not right yet, Skipped, Could not be checked, Co is still checking; softer words for kids), the answer only where the server revealed it, Co's feedback labelled "Co says", the explanation, a source link, and "Ask Co to check again" (one regrade request per attempt, double press is one request).

## Assumptions to conform with PD2 at integration

1. `SessionRow`, the `GET sets/:id` body, the session history page (`{ sessions|items, nextCursor }`), `AnswerSheet` (display strings `yourAnswer` and `correctAnswer`, `attemptId` while feedback is unavailable) and `PracticeSessionState` are not in the contract text. Shapes are in `lib/api/practice.ts`.
2. `PracticeSummary` and `AnswerSheet` carry an optional `band`; without it the page uses the signed-in child's band, then teens. **Recommend adding `band` to both responses** (a kid on an account-only session would otherwise get the teen layout).
3. `POST sessions` takes `clientSessionId` in the body; `POST sets` answers `{ set }`; `retry` answers `{ set }` and may return a new set id.
4. A DUE link with no id opens the hub (contract text); the hub's own review button starts it.
5. `PracticeSummary.xp|level|readiness` are typed `number | null` (the contract says `null`); non-numbers are dropped.
